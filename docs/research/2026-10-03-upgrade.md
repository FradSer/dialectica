# Research-driven upgrade: acceptance contract

Status: complete. This document preserves the original research
objective and chronological progress; earlier outstanding statements are
checkpoint observations superseded by the final acceptance section below.

## Objective derived from the README

Determine when additional inference computation improves task outcomes over a strong prompt-matched single call, and ship useful, measured workflows on the ADK kernel. Destructive local API/architecture upgrades are authorized. Real-model verification remains required. Preserve historical findings as dated observations, not universal impossibility claims.

## Required deliverables and gates

1. Broad primary-source literature search through 2026-10-03, including recent August/September papers, counterevidence, training requirements and negative results. Record source dates and reading depth; separate paper claims from local replication.
2. Replace weak measurement: invalid judges/errors cannot become ties; record each arm's input/output/total/cached/unknown usage, controller and verifier overhead, latency, model roster and raw outputs. Call matching alone is not token or dollar matching.
3. Restore a useful non-saturated evaluation surface: objective verifier-backed tasks and evidence-grounded open-ended decisions; separate development and held-out sets. Diagnose generation coverage separately from final answer selection. Do not tune on held-out outcomes.
4. Implement and compare plausible recent mechanisms, including targeted claim falsification and budget-aware orchestration with selective artifact context. Compare against prompt-matched single, repeated sampling/self-refinement, existing heterogeneous reflection, homogeneous controls and a direct-controller ablation where applicable.
5. Run real-model pilot experiments, then predeclared held-out comparisons with repeated trials and uncertainty. Saturation, missing metadata, provider failures and inconclusive comparisons must be reported explicitly. A green E2E is execution evidence, not superiority evidence.
6. Integrate mechanisms that meet the evidence gate into a coherent shipped API; keep failed or unproven variants as research modes. Explain breaking changes and migrations. Update English and Chinese READMEs from measured results, not desired outcomes.
7. Complete relevant regression/lint/package checks, fresh independent review for the new cross-module interfaces, and final live E2E. Audit every requirement against saved artifacts before marking the goal achieved.

## Initial audit

- Current baseline asks for a direct solution, while reflection synthesis asks for binding decisions, triggers and trade-offs: the claimed prompt matching must be rebuilt.
- Current harness counts calls through `run_agent`, not full token/latency costs per arm.
- Judge parsing permits arbitrary winner strings; an exhausted malformed measurement can silently become a tie. Add RED regressions before fixing.
- Historical strongest dialectic result used three problems and one judge; reflection uses five/ten tasks. Neither establishes a general law across models/tasks.
- Existing runtime reliability and real-model tests provide the execution substrate, not new quality measurements.

## Candidate selection

- Claim-level verification: training-free mechanism; isolate decisive claims and refute independently. Do not equate an LLM verdict with a ground-truth verifier.
- Meta-reasoning: separate assessment, proposals, value/cost evaluation and dispatch; use typed actions and artifact references. All controller calls count against the same budget.
- Semantic uncertainty: useful adaptive signal, but additional samples and unconstrained-budget experiments require careful cost controls.
- Learned Conductor/TRINITY/Fugu: architectural evidence, not a claim that prompting reproduces their RL/evolution-trained coordinator.
- Protocol/data separation: validate routing, visibility and stop/select actions in Python; optimize task content without allowing prompt text to change the execution protocol.

## Next implementation acceptance scenarios

- Given a finite call allowance, when assessment/proposal/evaluation/dispatch
  and workers execute, every call consumes the same outer allowance. A small
  budget must not cause an unmetered final synthesis or phantom artifact.
- Given stored artifacts with stable IDs, when a controller selects an earlier
  answer, the exact stored answer is returned. Unknown references fail before
  dispatch; a stop action cannot submit freshly generated text.
- Given a worker context list, when the worker executes, only those prior
  artifacts are supplied. Private controller state is not silently injected.
- Given identical worker/action interfaces, when staged and direct controllers
  are compared, both receive the same allowance and oracle access. Stage costs,
  artifact dependencies, coverage and selected-answer correctness are saved.
- Given protocol v2 malformed predictions, when consensus or CLR selects an
  answer, syntactically unparseable predictions are omitted without consulting
  the hidden optimum. If none remain, report explicit failure.
- Given development choices are frozen, when held-out trials begin, seed,
  model roster, budget levels, repetitions, order randomization and analysis
  rules are saved before any held-out result is observed.
